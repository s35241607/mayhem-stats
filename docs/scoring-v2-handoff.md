# Mayhem 新計分演算法：交給 Claude 的實作規格

日期：2026-10-17。狀態：可實作的候選設計，尚未完成新總分的資料回放與公平性校準。

請依以下需求實作候選計分器、輸出可解釋的分項，並用現有對局回放比較。前面的探索曾提出「同英雄歷史基準」與「開戰價值推算」，使用者後來已排除這兩個方向，以本文件為最新交接規格。

**需求已確定，數值參數尚未定案。** 本文件的 80／10／6／4 分配、職責模板、0.05 平滑量、增幅影響與功能裝額度，都是建議的原型起始值，不是使用者已確認的最終權重，也不是資料迴歸出的最佳值。把它們集中管理並標記版本；回放後可提出有證據的調整。

**1. 必須滿足的使用者需求**

- 以這場可觀測的工作評分。不用全體同英雄歷史平均、英雄百分位、玩家自己的歷史平均來規定應有表現。
- 同一英雄有不同操作與流派，不用英雄名稱或射手／法師／坦克等單一標籤硬決定整套公式。
- 同一人可同時輸出、承傷、控場、保人。輸出裝搭配小件防裝也要能逐步反映承傷職責，不用 30% 等門檻突然換公式。
- 清兵、推塔不是每個人的共同必考項，改成有限的正向加分。
- 低輸出、先死亡不等於開戰不好。不能推算關鍵開戰、吸收關鍵技能、犧牲價值或失誤死亡。
- 承傷可獨立計入，不要求先有高輸出、高助攻或隊伍勝利。
- 重創／降治療、破盾等功能性配置可取得額外獎勵；現有資料只能支持保守的配置獎勵，不能假裝知道實際阻止量。
- 不將擊殺、KDA、金錢收入、勝負直接當加分輸入。裝備價格若用於描述配置比例，不代表賺錢加分。
- 缺資料與確定為零必須分開。未知的工作不能宣稱為零貢獻。

**2. 候選分數的語意與計分範圍**

建議原型名稱：`本場貢獻 v2`；欄位可用 `work_score_v2`。

本文件選擇「同一場雙方十人」作工作量的比較範圍，排除所有跨場英雄／玩家基準。這是為完成原型而新增的設計建議，不是先前已經驗證的決策。

- 這是本場相對工作貢獻，不是操作實力、因果勝率或跨場絕對表現。
- 對手是比較範圍的一部分，因此同隊所有人可以比對手高；不用強迫每隊平均 50。
- 新總分的 50 沒有「同英雄中位數」的意思；不要沿用舊解說或舊色階門檻。
- 同配置、同數值在不同陣容／節奏下可能不同分。跨場平均只能作描述，不能稱為英雄熟練度或公平的玩家能力排名。
- 固定規則版本下，新增其他對局不影響本場分數。
- 同一效果只有一名提供者時，沒有足夠對照來辨識其絕對品質；本場正規化只能呈現工作分配。這個限制不能靠再多加一層排名解決。

只算 queue 2400、非重開、時長至少 360 秒、雙方各 5 人的完整對局。對局鍵用 `(platform_id, game_id)`，玩家列用 `participant_rowid`；不要在裝備或增幅展開後把人次重複計算。不完整對局回傳空分與原因。

**3. 輸入工作量**

令 `t = game_duration / 60`。以下均為每分鐘量；本場所有人時長相同，不能改成除以各自存活時間來放大高死亡者的工作率。

| 代號 | 定義 | 說明 |
|---|---|---|
| D | `dmg_to_champions / t` | 對英雄傷害 |
| T | `(dmg_taken + dmg_mitigated) / t` | 承受＋減免的承傷代理量，不稱為有效開戰或保護隊友 |
| C | `time_ccing_others / t` | 使用一個可解釋的控制秒數欄位；另一個 `cc_duration` 留作說明／敏感度比較，避免直接相加重複計算 |
| H | `(heal_on_teammates + shield_on_teammates) / t` | 只用有來源的治療／護盾隊友量，不用含自補的 `total_heal` 冒充 |
| W | `max(0, total_damage - dmg_to_champions - dmg_to_objectives) / t` | 清兵代理量，含未分辨的非英雄／非目標傷害，需在說明標示限制 |
| O | `dmg_to_objectives / t` | 目標傷害代理量；若改用原始 JSON 的 `damageDealtToTurrets`，須先核對覆蓋、定義及映射，再另版變更 |

不得默默將缺值 `COALESCE(..., 0)`。W 的負差先記異常再取零，不能以截斷掩蓋來源錯誤。T 的兩個來源缺任一項時標記部分觀測，不直接當作完整承傷量。

**4. 用配置建立連續職責，不從本場最高分倒推本職**

先算三個非負比例：`r_D`（輸出）、`r_T`（承傷）、`r_H`（保人），總和為 1。它們不使用本場傷害、承傷、勝負或歷史平均。

第一版可沿用 `builds.yml` 已有的裝備類別分攤方法，但需修改兩點：保留連續比例、不套六類定位門檻；納入持有的小件防裝／零件，不能沿用 `price >= 1500` 導致小坦裝完全消失。

具體原型規則：

- 檢查終場實際持有的 slot 0–5。依版本化的裝備功能表分配固定配置點數，初版可用物品總價作為點數，複合裝按所屬類別等分。
- 輸出類包含既有 AD／AP 裝備類別；承傷類包含生命、物防、魔防；保人類使用已核對的輔助裝備清單及效果。消耗品、飾品與只有移動效果的物品不形成職責；有明確防禦屬性的鞋子可以分到承傷。
- 這仍是粗略的配置代理，不是裝備每個屬性的精確效益。後續若改用 `dim_item_stats` 的實際屬性，先定義同單位轉換再回放，不直接把 300 生命與 30 攻擊相加。
- 同一持有物只算一次，不把成裝與它已消失的合成零件重複計入。
- 裝備點數歸一化成 `r_item`。完全無法辨識時以 `(1/3, 1/3, 1/3)` 作暫估，並標 `role_unknown`，不能宣稱已辨識流派。
- 可解析增幅另外提供三維非負向量，單個已知向量總和為 1。中性效果為零向量；未知效果另標未知，不能宣稱中性。設有效增幅欄位數為 K，`a = Σ 已解析增幅向量 / max(K, 1)`。
- 建議原型 `r = normalize(r_item + 0.25 × a)`；沒有增幅資料時使用 `r_item` 並標來源缺漏。0.25 是待校準的設計係數，不是增幅實際占比。將未解析數量與已解析證據另外輸出。
- 同一個增幅可以影響職責，也可有重創／破盾功能，但功能性加分按效果類別去重。不要把「影響職責」當成已發揮效果。

將 r 混合成四個主分權重：

| 職責模板 | D 輸出 | T 承傷 | C 控場 | H 保人 |
|---|---:|---:|---:|---:|
| 輸出 | 0.80 | 0 | 0.20 | 0 |
| 承傷 | 0 | 0.80 | 0.20 | 0 |
| 保人 | 0 | 0.20 | 0.30 | 0.50 |

`w_plan = r_D × 輸出模板 + r_T × 承傷模板 + r_H × 保人模板`

例如純裝備比例為輸出 75%、承傷 25%，在套用能力適用性前，權重是 D 60%、T 20%、C 20%。純承傷模板不要求傷害，但打出傷害仍可取得跨職責加分。

模板數值只是原型起點，需要回放檢查它是否過度偏向某類工作。

**能力適用性：** 靜態技能、裝備及增幅可用來判定有沒有控制／治療護盾隊友的能力，不可用來設定同英雄歷史達標線。建立帶版本與來源的 `yes / no / unknown` 映射。明確沒有 C 或 H 能力時，將該項主權重設零後歸一化；未知不能當作 no。若有實測正值卻映射為 no，要標記映射衝突並以觀測確認該功能存在，不可把實測貢獻丟掉；不要因實測量大而改選主職責。也不要把零觀測值當作沒有能力，讓應做卻沒做的工作自動消失。

**5. 缺值與適用性先處理，再比較**

- H 若雙方十人未全部取得有效的隊友治療／護盾統計，本場 H 不作跨人正規化；單獨已知的量可展示，不能與別人的未知零混排。
- 其餘軸若有人缺失，也不能用剩餘幾人的總量冒充完整十人；該軸本場暫停計分，保留缺值原因。
- 完整觀測的 0 是 0，仍保留該軸的適用主權重。
- `coverage_i = Σ 可觀測軸的 w_plan_i,k`，另存缺失軸與能力未知標記。
- 用可觀測軸重新歸一化得到 `w_i,k`。若剩餘權重總和為零，主分為 null，不給 0 或 50。
- 資料不完整時，總分顯示「暫估」及覆蓋狀態；不能因重分配而宣稱與完整資料同等可信。MVP／ACE 若仍依暫估分排序，必須標成暫估，不可給出無保留的官方結論。
- 清兵／目標代理量、配置未知、功能需求未知也要各自標記；不能只用主軸 coverage 假裝整份計分都完整。

**6. 將不同工作換成 0–100 的本場分項**

以下只使用這場十人的資料。對每個可觀測的主軸 `k ∈ {D,T,C,H}`：

```text
epsilon = 0.05                         # 原型平滑參數
a_i,k = epsilon + w_i,k                # 即使不是本職，也保留跨職責的比較尺度
X_k = Σ_j x_j,k                       # j 是本場雙方十人
A_k = Σ_j a_j,k
E_i,k = X_k × a_i,k / A_k             # 依連續職責分配的本場參考量

P_i,k = 0                             if X_k = 0
P_i,k = 100 × x_i,k / (x_i,k + E_i,k) otherwise
```

這裡的 E 是規則分配的參考工作量，不是由歷史資料估出的能力預測。

- 實際量等於參考量時 P=50；2 倍時約 66.7；4 倍時 80。報酬逐漸遞減，承傷不會無限線性加分。
- 工作量為零時該項為零。整場該項都是零時，不送中立的 50 分。
- 職責權重低的額外工作仍有機會加分；epsilon 防止直接拿零當分母，但 0.05 是否造成低職責者過度加分需要回放。
- 參考量包含本人，所以本場量尺與自我輸入有關。同一項只有本人提供時，增加絕對量可能不再提高分項，這是相對計分的限制，需明確報告。
- 檢查輸出、承傷、控場與保人是否因機制、陣容或資料缺漏而系統性偏移。這個公式不是已證明公平的標準。

**7. 總分由四部分組成**

```text
主分 B_i       = 80 × Σ_k(w_i,k × P_i,k / 100)
跨職責加分 X_i = 最高 10 分
推進加分 G_i   = 清兵最高 2 分 + 目標最高 4 分
功能配置 U_i   = 重創最高 2 分 + 破盾最高 2 分

S_i = round(clamp(B_i + X_i + G_i + U_i, 0, 100), 1)
```

80+10+6+4=100 是方便回放的初始分配，不代表四部分實際價值恰好為此比例。

主分達到各軸參考量時是 40 分，再另加有證據的加分；不能沿用「總分 50 是中位數」的文案。最終量尺分布需要回放檢查。

**跨職責加分的完整定義：**

```text
g(P) = max(0, (P - 50) / 50)
q_i,k = 1 - w_i,k

X_i = 10 × Σ_k(q_i,k × g(P_i,k)) / Σ_k q_i,k
```

只在資料可觀測的軸求和；分母為零時 X=0。主職責占比越高，這項工作的額外獎勵越低；超過參考量的其他工作可得到更多額外獎勵。主分與此獎勵是明示的兩段曲線，不再疊舊版近戰加成或坦克／輔助身分加成。

它不是「從這場最高的兩個數據回頭選本職」；主權重早已由配置與能力適用性決定。仍須檢查低權重工作是否因參考量太低而容易拿額外分。

**推進加分的完整定義：**

清兵 W 與目標 O 不分職責，採本場雙方十人的平均工作量作參考：

```text
R_k = Σ_j x_j,k / 10                  # k 為 W 或 O
P_i,k = 0                            if R_k = 0
P_i,k = 100 × x_i,k / (x_i,k + R_k)  otherwise

G_i = 2 × P_i,W / 100 + 4 × P_i,O / 100
```

這兩項為正向、有限的額外分，不從主分扣掉未清兵／未推塔的分數。不採清兵／推塔百分位，也不把勝負當額外加分。少量工作在全場總量很低時可能得到不成比例的相對加分，因此需要回放；上限本身不能保證完全不被刷分。

缺少 W 或 O 時，該項未知，不將其額度轉給另一項。若顯示已知部分總分，須同時顯示有未觀測加分；不要說未知項的實際貢獻是零。

**8. 重創／破盾的功能性配置加分**

先建立以效果為單位、帶版本的功能表。來源可以是裝備、已核對的技能或增幅；同一效果多個來源只形成一個候選資格，不能逐件疊加。原型先支援 anti_heal 與 anti_shield，其他光環、破防、減攻速等效果要逐一確認定義後再擴充。

對效果 f，敵方每個獨立的治療／護盾來源給 `s_j,f ∈ {0, 0.5, 1, unknown}`：

- 1：已核對的核心、持續或主要治療／護盾功能；0.5：已核對的條件性或附帶來源。
- 0：已確認沒有對應來源；unknown：資料或解析不完整。不能只因文字沒匹配到就當零。
- 認定須來自本場技能、裝備或增幅的版本化映射，不能用該英雄歷史平均治療量。不要把每位英雄一般生命回復都自動當成需要重創的核心來源。
- 同一機制的重複描述要去重；機制不明先 unknown。此強弱分類是規則，不是真實發動頻率。

```text
N_team,f = min(1, Σ 已核對敵方來源強度)

I_i,f = 1  if 持有/具備該功能，且觸發方式與配置可合理相容
I_i,f = 0  if 已確認沒有該功能，或觸發條件確定不可能
I_i,f = unknown otherwise

u_raw_i,f = 2 × N_team,f × I_i,f
```

對 N 或 I 為未知的未覆蓋部分，保留狀態，不擅自猜實際觸發。有明確敵方來源時可給已確認部分的獎勵，即使其他來源尚未解析；完全沒有已確認來源但仍有未知時，不能說需求為零。

建議同隊每類效果設 6 分總上限：

```text
u_i,f = u_raw_i,f × min(1, 6 / Σ_team u_raw_j,f)
U_i = u_i,anti_heal + u_i,anti_shield
```

分母為零時已確認加分為零，未知狀態另存。6 分是限制重複配置獎勵的預算，不是推算誰真正覆蓋了目標；不是一見多人持有就一律除以人數，更不是只有第一個人有效。個人 U 上限為 4 分。

必須保留以下限制：

- 現有資料沒有實際阻止治療量、削減護盾量、目標覆蓋或完整持有時間。這項只能叫「功能性配置」，不能叫實際減療／破盾成效。
- 不用敵方最終治療量乘物品比例來估阻止量；敵方最終治療少可能已經受到重創影響。
- 區分觸發方式，例如受到普攻與主動造成特定傷害不是相同條件。可用性不代表真的命中到需要壓制的那個目標。
- 只有終場裝備，不能證明早早補裝或整場覆蓋。額度保守，且承認終場補買刷配置分的限制；不要虛構購買時間。
- 對物品說明中的 0%、占位符等未正確填值，不能當成當局效果數字。
- 已被 H 等實測工作量計入的同一治療／護盾效果，不因買了該裝再重複領功能裝獎勵。
- 若未來取得直接效果統計，另版以效果量取代代理獎勵，不能兩份加滿。

**9. 死亡、開戰與舊加成的處理**

建議原型的死亡直接扣分係數設為 **0**，死亡數與死亡時間獨立展示。這是為避免無法辨識開戰品質而設的原型選擇，使用者尚未確認最終死亡成本。

- 移除 `damage / sqrt(deaths + 1)`、`soak / sqrt(deaths + 1)`，改用第 3 節的每分鐘工作量。
- 不因先死、傷害低而扣開戰分，也不因後續打贏／拆塔而送犧牲分。
- 不同時用死亡比例、KDA、輸出效率、承傷效率重複扣同一件事。
- 不保留舊版近戰、坦克或輔助身分的固定正向加成。
- 如要比較死亡輕扣版本，另開版本與參數，最多只計一次、上限有限，並拿低輸出高承傷的匿名案例檢查。不能將它混進預設而不說明。
- 承傷遞減只防止無限線性加分，不能保證辨識無效吃傷；回放仍要檢查高死亡低工作與低輸出高承傷兩類案例。

**11. 偽程式與輸出契約**

```python
def score_match(match, players, rules):
    validate_unique_complete_5v5_match(match, players)
    if match.is_remake or match.duration_seconds < 360:
        return unscored("remake_or_short_game")

    workload = read_observed_workload(players)  # null 與 0 分開
    capability = resolve_versioned_capabilities(players, rules)
    responsibility = mix_items_and_known_augments(players, rules)
    planned_weights = mix_templates(responsibility, capability, rules)

    availability = shared_axis_availability(workload)  # 不用殘缺十人總和
    coverage = observed_planned_weight(planned_weights, availability)
    weights = renormalize_observed_weights(planned_weights, availability)
    components = normalize_within_match(workload, weights, rules.epsilon)

    base = weighted_base(components, weights, rules.base_budget)
    extra = capped_off_duty_bonus(components, weights, rules.extra_budget)
    progress = bounded_wave_and_objective_bonus(workload, availability, rules)
    utility = contextual_function_bonus(players, capability, rules)

    return score_and_known_additions(
        base, extra, progress, utility,
        coverage=coverage,
        missing=availability.missing,
        unknown=capability.unknown,
        rules_version=rules.version,
    )
```

**13. 驗收與回放要求**

1. **不依賴歷史池：** 固定規則下，新增不相關對局，不改變已算對局的 v2 分數。
2. **不同流派：** 同英雄的輸出、半坦、保人配置有不同連續權重，不能由英雄名稱固定一套。
3. **小防裝：** 增加防禦配置比例時權重連續變化；不出現 29.9%／30.0% 的整套定位跳變。
4. **前排低輸出：** 純承傷配置可以靠承傷、控場得到主分，不要求傷害或助攻；死亡數改變、其他工作與配置不變時，預設 v2 分數不變。
5. **跨職責：** 固定其他人的資料、配置與規則，增加自己的額外工作不應使自己的分數下降；同時檢查 low-weight 軸的獎勵是否過大。
6. **清兵／推塔：** 不提供這兩項不扣主分；全場為零不送分；兩項不能突破 6 分上限。
7. **功能裝：** 明確有對應需求且配置合理時可加分；無需求、需求未知、條件不可能分開處理；同人多件同類不疊滿；隊伍預算正確，且不宣稱覆蓋歸因。
8. **缺值：** H 沒資料不能填零；確定為零不能當作缺值移除權重；不完整參考池不能冒充十人資料。
9. **分數分布：** 用對局為單位查看各配置、時長、版本、資料完整度的分布與極端案例。檢查總分是否過度擠在某區間、過多滿分，或某種配置僅靠尺度得到固定優勢。
10. **可操弄性：** 特別抽查反覆承傷、低傷害低參與、純清兵、終場補功能裝、零成本功能觸發等案例。資訊不足的部分如實列出，不宣稱已解決。
11. **數字核對：** 依專案 `verify-change` skill，以獨立手寫 SQL／獨立算式核對分項與總分。不要只拿正式實作自己驗自己。
12. **參數敏感度：** 對主要權重、epsilon、額度做適度擾動，比較同場名次與 MVP／ACE 變更；若輕微改值就大量翻轉，要列出原因及案例。不要先預設某個翻轉比例就是好壞標準。
